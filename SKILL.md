# Exa: поиск и ресёрч

Всё через скрипт `${CLAUDE_SKILL_DIR}/scripts/exa.py` в Bash: прямой REST API, MCP не нужен,
только стандартная библиотека Python 3.10+. Вывод компактный, его размер задаёшь сам — так
тратится в разы меньше токенов, чем через MCP. Если `${CLAUDE_SKILL_DIR}` не подставился (другой
агент, не Claude Code), это папка, где лежит этот `SKILL.md`.

```bash
E="python ${CLAUDE_SKILL_DIR}/scripts/exa.py"   # на macOS/Linux — python3
$E search "описание идеальной страницы" -n 5 --chars 400 [--since 2026-10-01] [--domain github.com]
$E fetch https://... [https://...] --chars 3000
$E agent "задача" --effort medium [--schema '{...}' | --schema файл.json]
$E agent --resume agent_run_...
```

## Какую команду брать

| Задача | Команда | Цена, время |
|---|---|---|
| Факт, справка, найти страницу | `search -n 3..5 --chars 300..600` | ≈ $0.007, секунды |
| Прочитать известный URL | `fetch --chars` по нужде | ≈ $0.001 за страницу |
| Точечный вопрос с источником, низкая цена ошибки | `agent --effort low` | ≈ $0.025, ~30 с |
| Проверенный факт, ресёрч со сверкой | `agent --effort medium [--schema]` | ≈ $0.10, 40–70 с |
| Широкий обзор за период, много платформ | `agent --effort high` | ≈ $0.50, 3–4 мин |

- Начинай с малого: `-n 3 --chars 300`, добирай `fetch` только по нужным URL.
- Считай поиски: десятки мелких `search` подряд дороже по токенам, чем один `agent --effort medium`
  со схемой ($0,10 вместо 15+ × $0,007 и тысяч символов в контексте). Если нужно больше ~10 поисков
  по одной теме — бери `agent`.
- Запрос в `search` — описание идеальной страницы, а не ключевые слова.
- `agent` сам ждёт результат (до 15 мин), долгий запускай в фоне. Если скрипт сказал «Ещё идёт» —
  `agent --resume <id>`, новый run не создавай.
- В `--schema` у каждого факта поле URL и даты, массивы с `maxItems`. В задаче проси
  первоисточники, точные даты, пометку «заявлено разработчиком / измерено независимо».
- Сомнительный факт перепроверь `search` по первоисточнику.
- `xhigh` ($1) почти никогда не нужен: на бенчмарке из 10 фактических вопросов он не точнее
  `medium`. Баллы из 30: search 28, agent medium 27, xhigh 27, low 26, deep 26, WebSearch 23.
- `agent --effort low` может выдать устаревший факт как текущий — для важных фактов бери `medium`.
- `--type deep` на русских запросах не использовать: на бенчмарке вернул ноль результатов.
- Слабое место Exa — новости последних дней: бывает пустая выдача. Тогда переформулируй запрос
  или добавь `--since`.

Методички Exa в `references/` (из exa-labs/exa-mcp-server, MIT) написаны под MCP-инструменты,
соответствие: `web_search_exa` → `exa.py search`, `web_fetch_exa` → `exa.py fetch`,
`agent_run` → `exa.py agent`. Запросы — `references/searching.md` (+ `patterns-*.md` по типу
задачи), большой ресёрч с субагентами — `references/search-method.md`, тонкости Agent —
`references/agent-run.md`.

## Пул ключей

Ключи — в `.env` в папке скилла, нумерованные строки `EXA_KEY_1=...`, `EXA_KEY_2=...` и дальше;
порядок строк = приоритет. Переменная окружения `EXA_API_KEY` подхватывается последней как `env`
(если её значение уже есть в `.env`, второй раз не считается). При 401/402/403/429 скрипт повторяет
запрос со следующим ключом, упавший откладывает (402 — 6 ч, 429 — 2 с, 401/403 — неделя); если 429
у всех ключей — ждёт и повторяет до 3 раз. Лимит — 10 запросов в секунду на команду (team): не
запускай больше ~8 поисков разом. Agent run опрашивается тем ключом, на котором запущен.
Состояние и журнал пула — `.tmp/` в папке скилла (в журнале только имена ключей). Каждая команда
печатает в конце `[key <имя>, $цена]`.

```bash
$E status       # каждый ключ: работает / нет баланса / отозван (1 поиск ≈ $0.004 на ключ)
$E add          # новый ключ под следующим номером: скрытый ввод, проверка, запись в .env
$E reset        # снять отметки «ключ упал»
```

- Ключ в чат не принимай и сам в `.env` не вписывай: попроси пользователя выполнить `add` в его
  терминале или дописать строку в `.env`. Значения ключей не печатай и никуда не пиши.
- Ключи одной команды (team) делят и баланс, и лимит 10 QPS: пул помогает, только если ключи
  из разных команд.
- Баланс и сроки кредитов видны только в дашборде: dashboard.exa.ai/billing. Первыми списываются
  кредиты, которые сгорают раньше.
- Если все ключи отказали — сказать пользователю одной строкой, что ключи пусты или отозваны.

## Журнал расходов (по желанию)

Если задан `EXA_USAGE_FILE` или в папке скилла есть `data/usage.jsonl`, каждый вызов
`search`/`fetch`/`agent` пишет туда строку: время, команда, запрос, цена, объём ответа, папка
проекта. По умолчанию журнал выключен.
